# Products API

A RESTful API built with **ASP.NET Core 10** following **Clean Architecture** and the **CQRS** pattern.

## Features
- Clean separation: Domain / Application / Infrastructure / API
- CQRS with MediatR (Commands & Queries)
- Request validation with FluentValidation via a MediatR pipeline behavior
- Global exception handling returning standard `ProblemDetails`
- EF Core 10 with SQL Server and the Repository pattern
- DTOs separate from domain entities
- Structured logging with **Serilog** (Console + rolling file sinks) using the `ILogger<T>` abstraction
- Request logging via `UseSerilogRequestLogging()` and a MediatR `LoggingBehavior` for Commands/Queries
- Request tracing using a **Correlation Id** (`X-Correlation-Id` header)

## Architecture
Api → Application ← Infrastructure
↓
Domain
Dependencies always point inward toward the Domain layer.

## Tech Stack
.NET 10 · EF Core 10· SQL Server · MediatR · FluentValidation · Serilog  · Swagger

## Endpoints
| Method | Route | Description |
|---|---|---|
| GET | /api/products | Get all products |
| GET | /api/products/{id} | Get product by id |
| POST | /api/products | Create a product |

## Logging

The project uses **Serilog** configured from `appsettings.json`, while the Application and
Infrastructure layers depend only on `ILogger<T>` (Microsoft abstractions). Only the API layer
knows about Serilog, so the logging library can be swapped without touching the handlers.

### Sinks

| Sink | Location | Details |
|---|---|---|
| Console | Terminal | Real-time output during development |
| File | `logs/log-.txt` | New file every day, last 7 days retained |

### What gets logged

| Source | What it logs |
|---|---|
| `UseSerilogRequestLogging()` | One line per HTTP request (method, path, status code, duration) |
| `LoggingBehavior` | Every Command/Query name and its execution time |
| `GlobalExceptionHandler` | Validation failures (Warning), not found (Warning), unhandled errors (Error) |

### Configuration

```json
"Serilog": {
  "MinimumLevel": {
    "Default": "Information",
    "Override": {
      "Microsoft.AspNetCore": "Warning",
      "Microsoft.EntityFrameworkCore.Database.Command": "Warning"
    }
  },
  "WriteTo": [
    { "Name": "Console" },
    {
      "Name": "File",
      "Args": {
        "path": "logs/log-.txt",
        "rollingInterval": "Day",
        "retainedFileCountLimit": 7
      }
    }
  ]
}
```

To see the SQL generated by EF Core, change `Microsoft.EntityFrameworkCore.Database.Command` to `Information`.

### Correlation Id

Every request gets a `CorrelationId` (taken from the `X-Correlation-Id` header or generated automatically),
added to all log entries and returned in the response headers, so a single request can be traced end to end.

## Getting Started
1. Update the connection string in `Products.Api/appsettings.json`
2. Apply migrations:
   `dotnet ef database update -p ProductsApi.Infrastructure -s Products.Api`
3. Run: `dotnet run --project Products.Api`
4. Open Swagger at `https://localhost:<port>/swagger`
